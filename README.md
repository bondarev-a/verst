# Verst

Версия 0.4.7.

Локальный редактор текстовых файлов. В меню и на ярлыке программа называется Verst, заголовок окна — Text Workspace. Основной формат — Markdown: слева исходник, справа собранная страница. Остальные текстовые файлы тоже открываются и правятся. Обход сразу по всему диску. Каталог можно запинить как пространство: внутри него работают поиск, входящие ссылки и граф.

Границы продукта — в [requirements.md](./requirements.md). Что вошло в каждую версию — в [release_notes.md](./release_notes.md) и в [релизах](https://github.com/bondarev-a/verst/releases).

## Установка на Ubuntu

Нужна Ubuntu 24.04 или новее, архитектура amd64. На машину, куда ставят уже собранный пакет, Rust не нужен. Пакет зависит от `libgtk-4-1`, `libgtksourceview-5-0`, `libwebkitgtk-6.0-4`, `bubblewrap`, `xdg-dbus-proxy` и AppArmor. На Ubuntu 22.04 этих библиотек нет.

Готовый пакет лежит в [релизах](https://github.com/bondarev-a/verst/releases): файл `verst_<версия>_amd64.deb`. Каждый пуш в `main` выкладывает пакет этой версии. Текст релиза берётся из раздела этой версии в [release_notes.md](./release_notes.md).

```bash
wget -O verst_0.4.7_amd64.deb \
  https://github.com/bondarev-a/verst/releases/download/v0.4.7/verst_0.4.7_amd64.deb
sudo apt install ./verst_0.4.7_amd64.deb
```

После установки программа называется `verst` и появляется в меню.

## Файлы

Над текстом виден полный путь к открытому файлу. У Markdown три вида: редактирование, рендеринг и просмотр. Список «Вид» над текстом переключает текущий файл. Рендеринг правит тот же текст в редакторе: заголовки и выделение видны собранными, таблица становится сеткой, правки пишутся обратно в Markdown. Просмотр — страница WebKit из текущего буфера; из неё же собирается PDF. Остальные текстовые файлы открываются в редактировании или в просмотре. В настройках пункт «Открывать» задаёт вид для файла, у которого он ещё не выбран.

- Сохранить (`Ctrl+S`). Правка также записывается сама, через короткое время после изменения.
- Сохранить как (`Ctrl+Shift+S`). Текущий текст записывается в выбранный файл, и документ переходит на него. Прежний файл на диске остаётся в последнем сохранённом виде.
- Сохранить PDF. Страница предпросмотра Markdown записывается на лист A4, с фоном блоков кода и картинками из каталога файла.
- Перейти к файлу (`Ctrl+P`).
- Закрыть (`Ctrl+W`).
- Файл из проводника или пространства можно перетащить в другое приложение. Файл, брошенный на окно извне, открывается.

Если открытый файл изменили снаружи, программа спрашивает, оставить текст редактора или перечитать диск.

## Заметки

Быстрая заметка (`Ctrl+N` или меню «Файл») создаётся в личном каталоге `~/.local/share/text_workspace/notes` и сразу открывается в редактировании. Список живёт в разделе «Заметки», отдельно от пространства.

Теги пишутся в тексте как `#тема`. Меню «Группировка» рядом с «Новая заметка» собирает список без групп, по дате создания, по дате изменения или по тегам. Список тегов по умолчанию свёрнут: раскрытие показывает до трёх строк, кнопка «Все теги» поднимает предел до пяти строк и включает прокрутку.

Заметку можно удалить из её строки; программа сначала спрашивает подтверждение. Кнопка «В пространство» сначала спрашивает, в какое пространство перенести заметку, затем открывает диалог сохранения уже в каталоге этого пространства.

## Навигация

Под меню «Файл» стоит полоса «Открытые файлы». Щелчок по имени открывает файл, крестик закрывает его, текущий файл подсвечен. Переключение не двигает файлы в списке и возвращает курсор туда, где файл смотрели. Если имён много, полоса прокручивается.

Слева разделы стоят вертикальной панелью: Проводник, Пространства, Заметки, История. Над панелью показан каталог, который сейчас активен в проводнике, пространстве или заметках. У каждой иконки есть подсказка. Внизу панели — булавка и кнопка, которая сворачивает навигацию и в свёрнутом виде разворачивает её обратно.

Справа вкладки «Оглавление», «Поиск», «Ссылки» и «Граф». Навигацию и блок «О файле» можно свернуть; булавка фиксирует их открытыми.

Раздел «Пространства» открывается списком каталогов. Выбор имени показывает дерево только этого пространства; кнопка «Все пространства» и повторный вход в раздел возвращают список. Файл в этом дереве и в содержимом каталога открывается одним щелчком. В проводнике каталог по-прежнему раскрывается двойным щелчком и Enter, стрелка у строки тоже разворачивает ветку. Содержимое каталога в центральной колонке открывается из меню строки, пункт «Показать содержимое».

Пространства переключаются `Ctrl+1`…`Ctrl+9`, а также `Ctrl+Tab` и `Ctrl+Shift+Tab`. Панель редактора можно разделить. Поиск по содержимому, входящие ссылки и граф считаются внутри активного пина. Исходящие ссылки открытого файла берутся из его текста и ведут в тот запиненный каталог, где лежит файл.

Масштаб окна: `Ctrl++` и `Ctrl+-`. На клавиатуре, где плюс набирается через Shift, срабатывает и `Ctrl+=`. Назад и вперёд по открытым местам — `Alt+Left` и `Alt+Right`. Найти в файле — `Ctrl+F`.

## Стек

- язык / runtime: Rust
- пакетный менеджер: Cargo
- основные зависимости: GTK 4, GtkSourceView 5, WebKitGTK 6
- платформа: Linux

## Сборка

Собрать пакет можно на Ubuntu 24.04+, где стоят Rust и заголовки библиотек.

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
sudo apt install pkg-config libgtk-4-dev libgtksourceview-5-dev libwebkitgtk-6.0-dev
./packaging/install_ubuntu.sh --deb
sudo apt install ./packaging/out/verst_0.4.7_amd64.deb
```

`./packaging/install_ubuntu.sh --deb` только собирает пакет в `packaging/out/` и ничего не ставит. Без флага скрипт ещё копирует программу в `~/.local/bin` и ставит ярлык в меню текущего пользователя. `./packaging/install_ubuntu.sh --system` ставит пакет в систему через apt.

Если `pkg-config` не видит GTK, потому что заголовки лежат в локальном префиксе, перед сборкой выполните `source ./env.sh`.

## Другие платформы

Библиотека в `src/lib.rs` не зависит от GTK: разбор Markdown, индекс ссылок, поиск, граф, сессия и масштаб. Её можно собирать на другой системе как есть.

Окно собрано в `src/ui/` на GTK 4, GtkSourceView 5 и WebKitGTK 6. Эти библиотеки есть в Linux-дистрибутивах с достаточно новым GNOME. Тот же исходник переносится на другой дистрибутив пересборкой и своими именами пакетов, не файлом `.deb` от Ubuntu.

Windows и macOS этим интерфейсом не покрываются: WebKitGTK туда не ставится как обычная библиотека. Чтобы перенести продукт, библиотеку оставляют, а `src/ui/` заменяют на окно той платформы. Предпросмотр Markdown на Windows логично отдать WebView2, на macOS — WKWebView. Путь сессии сейчас считается по XDG; для других систем его задают в `config_dir()`.

## Запуск из исходников

Те же заголовки, что и для сборки пакета:

```bash
sudo apt install libgtk-4-dev libgtksourceview-5-dev libwebkitgtk-6.0-dev pkg-config
cargo run --bin text_workspace
```

Сессия пишется в `$XDG_CONFIG_HOME/text_workspace/session.json` или в `~/.config/text_workspace/session.json`. Отдельного файла настроек нет: список пинов, открытые файлы, панели и масштаб хранятся в сессии.

Если процесс сразу завершается с `Failed to fully launch dbus-proxy`, песочница WebKit не смогла вызвать bubblewrap. Для запуска в таком окружении:

```bash
WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1 cargo run
```
